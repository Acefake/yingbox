# NAS 网盘、直播与通知修复计划

目标：网页端可进入网盘；NAS 代理远程直播播放列表、线路探测和 XMLTV；服务端发送 Bark / Telegram 入库通知。

设计：扩展现有 HTTP 契约域登记表，由 app 统一登记路由，网盘关闭时直播与通知仍可用。复用直播解析与推送服务，密钥只写入服务端 secrets.json，网页仅获取配置状态。直播出网沿用播放代理的逐跳校验与内网放行名单。系统通知和本地文件对话框保留桌面端。

- [x] 后端：共享域路由、直播与节目单、通知配置/密钥/测试接口、片库与追更事件接线及退出清理。
- [x] 前端：平台桥接、网页网盘入口、直播播放代理、通知设置和准确的平台提示。
- [x] 测试：先验证缺失接口，再覆盖鉴权、禁用网盘、直播私网策略、EPG、通知保存与实际入库事件。
- [ ] 交付：更新 ADR 与部署说明，类型/模块及全量检查，独立审查，提交推送并开 PR。

验证：类型检查、相关模块测试、桌面 / Web / 服务端构建、样式 / 大小写 / 体积 / 文案检查通过。浏览器实测远程播放列表、XMLTV、网页网盘入口与本机 Bark 测试推送通过；未验证真实 NAS 与真实通知设备。全量测试 3741 通过、11 跳过，1 个已有静态文件权限用例在 Windows 失败（chmod(0) 未阻止读取）。独立评审发现的网页视频代理、密钥写入顺序与退出等待问题已修复。
