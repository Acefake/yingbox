# CMS 源健康缓存与用户选择

用户已确认：保存用户开关，启动用缓存、后台复测过期记录；连续失败临时跳过，冷却后恢复尝试；手动重试立即生效，新增订阅源默认开启。

## 数据与边界

- `online_selected_sites` 仅代表用户选择，测活、搜索与详情均不修改它。
- 新缓存按完整 API 地址、能力 `browse/search/detail` 分开记录 `checkedAt/failures/until/error`，保存到 localStorage。
- 健康记录有效 30 分钟；前两次失败分别在 1、5 分钟后允许后台再测；连续第三次失败冷却 30 分钟。
- 搜索冷却不影响详情。列表探测成功不清除搜索错误。手动重试清除该源的冷却，列表先复测，搜索与详情通过下一次实际请求验证。
- 插件保留现有按用途熔断。CMS 状态由同一前端模块管理，桌面与网页调用同一模块；不改后端协议、无 token 模式及播放策略。
- 保留旧版已保存的启用选择，无法推断此前取消勾选属于自动还是手动；不自动批量重开。

## 检查点与实现

1. `features/online/utils/cms-health.ts` 定义纯状态转换、缓存校验和到期规则；`composables/cms-health.ts` 持久化状态及展示说明。`tests/cms-health.test.ts` 验证阈值、分能力隔离、缓存过期、手动恢复及非法缓存。
2. `use-source-refresh.ts` 删除自动修改开关的逻辑，默认后台检测只处理启用且过期的源，手动检测可强制执行；提供可销毁的后台监视器，由 `AppLayout.vue` 生命周期持有。保留所有来源共用的 6 并发上限。`cms-subscription.ts` 移除源时清理健康缓存，新源默认开启，既有手动关闭继续保留。
3. `use-online-search.ts` 使用能力健康状态跳过冷却源，将真实搜索和详情的结果写回缓存；使用 `skippedCms` 向搜索页及统一搜索入口显示跳过信息。取消或过期搜索不写入健康状态。
4. 内置、自定义、订阅列表显示健康说明及重试；删除自定义源时清缓存。工具栏失效统计使用同一状态；主动批量停用仍需用户点击。测试更新为保持用户开关的行为，并覆盖冷却、手动强制、混合并发及重启缓存。
