# 客户端基准下的手机、平板与电视适配

## 目标与边界

按已确认的客户端 UI Kit 落地网页和安卓的自适应外壳、首页与设置。复用图标、令牌、玻璃材质及已有设置内容，不改变服务接口、设置存储范围或播放协议。桌面客户端保持基准外观。网页电视浏览器的遥控器行为不在本次原生电视验证范围。

## 执行任务

1. 网页布局：修改 `composables/use-platform.ts`，明确手机、平板与触摸能力；在 `features/shell/AppLayout.vue` 让平板默认使用紧凑侧栏，手机使用浮动玻璃底栏。手机横屏和 iPad 分屏按可用空间切换，窗口扩大后恢复导航。
2. 网页设置：在 `features/settings` 增加页面导航状态，手机显示分类列表、进入二级页面，返回及关闭保留未保存确认；平板与桌面维持左右分栏。修改 `SettingsPanel.vue`、`ui/SettingsNav.vue`，使用共享按钮和焦点/逃逸层。已有显式分区链接直接打开详情，普通设置入口展示分类。
3. 首页：修改 `HomeHero.vue`、`home-hero.css` 及其数据，手机选竖版封面、居中内容、限制简介行数、缩略图改为紧凑指示；平板维持横向背景与内容货架。所有动作沿用现有调用。
4. 安卓：新增 `AdaptiveLayout.kt` 和分类设置壳；按手机、平板、电视组织现有设置，提取外观及元数据内容，保留语言保存失败回滚、NAS、源检测和更新。玻璃面板与背景分开绘制，避免模糊采样自身。电视提供分类与内容间的焦点恢复，手机返回只退出当前设置子页。
5. 安卓共享控件：导航按空间约束选择顶部/底部；平板留白与首页比例、电视阅读尺寸和触摸目标按设备适配，保留现有焦点环及降低透明度。

## 验证

- Vitest：增加设置页面导航行为回归，验证返回被拒、异步导航不会覆盖新状态、显式打开分区；运行既有设置导航、注册表、侧栏导航、首页测试。
- 网页：`pnpm typecheck`、针对性 ESLint、`pnpm check:style`、`pnpm check:case`；构建 NAS 网页。使用 390×844、768×1024、1024×768、桌面尺寸检查真实组件/页面，检查手机返回、分类搜索、分屏重排及横向溢出。
- 安卓：对设备分类添加 JVM 测试，运行 `:app:testDebugUnitTest :app:compileDebugKotlin`；可用模拟器时构建安装并检查手机、平板和电视设置。没有设备或构建受环境阻塞时报告准确边界。
- 自审完整差异和设置/导航调用方；完成后委派只读独立评审并处理任务内发现。不提交、不推送、不部署。

## 实施与验证记录

- 网页新增手机、平板窗口分类；平板可手动展开侧栏。手机设置分类与二级页面保留离开确认，平板缩窄时保持当前编辑器挂载。
- 安卓设置分为外观、刮削、网络优化、在线源、播放器、NAS 和关于与更新。保存任务由应用宿主持有，处理中不切换分类，避免网络配置的服务端与设备写入被分类卸载打断。
- `pnpm typecheck` 通过；相关 Vitest 覆盖 40 个用例。ESLint、style、case、size、copy 与 NAS 网页构建通过。机械视觉检测未返回发现。

- 实际 Chromium 页面验证手机首页、设置分类/搜索、Esc 逐级返回、768×1024 和 1024×768 双栏、507px 分屏、侧栏展开及编辑器挂载保留。检查范围内没有横向溢出或页面异常。
- 手机与电视模拟器已安装测试包；验证手机分类返回、平板尺寸下的双栏，以及电视方向键进入内容、返回后恢复分类焦点。模拟器导航检查未出现 AndroidRuntime 致命异常。
- 自审及独立评审已完成；保存生命周期问题已修复并复审通过，分屏编辑器保留另经只读复审。iPad Safari 实机和实体电视尚未验收；未发布或部署。
