# 安卓手机与电视播放器控制层重构（参考 Infuse）

- 日期：2026-11-07
- 状态：待审阅
- 相关：ADR-0039（播放内核）、ADR-0041（控制层）、ADR-0042（诊断）

## 1. 目标与范围

重做安卓手机与电视播放界面的**控制层**，让交互和观感接近 Infuse：手机按 iOS 触屏习惯，电视按 tvOS 遥控器习惯。

- 要改：`ui/` 下盖在画面上的 Compose 控制层、手势、遥控器键位、选项入口。
- 不改：播放内核（`PlayerState`、解码与降级、轨道、画质增强、统计与诊断、续播与进度上报）。
- 第二阶段（本次不做）：选集侧栏、章节列表、进度条缩略图、字幕样式设置。
- 成功标准：
  1. 手机一只手能完成：唤出控制层、拖进度、换字幕/音轨/倍速，不进深层面板；
  2. 电视只用方向键、确定键、返回键完成全部操作，每个键在同一状态下含义唯一，焦点始终可见；
  3. 原有能力不退化：杜比视界/HDR 信息、画质增强开关与对比、错误与降级提示、沉浸式横屏。

## 2. 手机端

保持横屏沉浸（ADR-0041 第 7 条不变），画面仍由 `PlayerView` 渲染。

- **顶部**：左侧圆形返回钮，紧跟两行标题（片名；集名或 S01E03，小一号灰字）。右上角一排图标：字幕、音轨、倍速、画面比例、画质增强、信息。点图标弹出小浮层直接选值，选完关闭，不进深层设置面板。
- **中间**：屏幕正中三个大圆钮：快退 10 秒、播放/暂停（最大）、快进 10 秒。
- **底部**：细进度条，左已播时间、右剩余时间；上一集、下一集是进度条两端的小图标，没有时不显示。底部不再放其他按钮。
- **拖进度**：横向滑动屏幕也可拖，画面中央显示“目标时间与当前差值”，松手才 `seekTo`；拖进度条时时间标签跟手。
- **手势**：单击唤出/隐藏；双击左右半屏快退/快进 10 秒；长按两倍速；左半屏竖滑亮度、右半屏竖滑音量（提示改成屏幕边缘竖条）；横滑拖进度。
- **材质**：玻璃只用于顶部按钮和中间圆钮；底部进度区用渐变压暗，不用整条玻璃。4 秒无操作自动隐藏，暂停、拖动、浮层打开时不隐藏。

## 3. 电视端

只靠方向键、确定键、返回键。

**控制层隐藏时（播放中）**

| 键 | 行为 |
| --- | --- |
| 确定 | 暂停/播放，并唤出控制层 |
| 左 / 右 | 拖进度：单击 ±10 秒，按住连发加速（10 秒 → 30 秒 → 1 分钟 → 5 分钟）；屏幕中央显示目标时间，松开或停 0.8 秒后才 `seekTo` |
| 上 | 唤出控制层 |
| 下 | 打开“信息与选项”面板 |
| 返回 | 退出播放 |

**控制层显示时**：焦点默认在中间的播放/暂停；方向键只在可见按钮间移动；获得焦点的按钮放大加亮；进度条上左右键用同一套加速拖进度；返回键先收起控制层，再按退出。

**信息与选项面板**：从底部升起的玻璃面板，横排四列：字幕、音轨、倍速、画面比例；列间左右切换，列内上下选值，确定后面板关闭；同时显示片源格式（分辨率、HDR/杜比视界、音频格式），取代顶部徽标；返回键关闭面板，焦点回到播放界面。画质增强开关放在面板里。

## 4. 代码结构

播放内核不动，旧的 `PlayerControls.kt`、`PlayerSettingsSheet.kt` 删除，`PlayerHost.kt` 瘦身。新增 `ui/player/`：

| 文件 | 职责 |
| --- | --- |
| `PlayerHost.kt` | 画面、手机/电视判断（沿用 `LocalIsTv`）、选布局、返回键与沉浸式 |
| `PhoneOverlay.kt` | 手机控制层布局 |
| `TvOverlay.kt` | 电视控制层布局与焦点高亮 |
| `TvOptionsPanel.kt` | 电视底部选项面板 |
| `PhoneOptionsPopup.kt` | 手机顶部图标弹出的浮层 |
| `OptionLists.kt` | 字幕/音轨/倍速/比例的选项数据与选择逻辑，手机电视共用 |
| `PlayerGestures.kt` | 手机手势，新增横滑拖进度 |
| `RemoteKeys.kt` | 电视键位到动作的映射 |
| `Scrubber.kt` | 拖进度的共用状态：目标时间、松手才 `seekTo` |

**纯函数**（放 `playback/engine/`，有 JVM 单测）：

- `remoteSeekStep(pressCount, heldMs)`：长按加速步长；
- `scrubTarget(startMs, dragPx, widthPx, durationMs)`：横滑换算目标时间，限制在 `0..duration`；
- `remoteAction(key, mode)`：mode 为隐藏 / 控制层 / 面板，输出唯一动作；
- 沿用 `formatClock`、`gestureDelta`、`playbackBadges`、`speedLabel`。

**数据流**：`PlayerState` 是唯一状态来源，控制层只读它并通过回调修改；拖进度期间的目标时间只存在 `Scrubber`，松手才 `seekTo`，并先把位置落到松手处，避免滑块弹回旧位置。

## 5. 错误与边界

- 直播或时长未知：进度条不可拖，时间显示 `--:--`，横滑与遥控器拖进度禁用。
- 没有上一集/下一集：图标不显示，不占位。
- 没有字幕或音轨：对应项显示“无”，不可选。
- 电视布局不出现任何必须触摸才能用的元素。
- 降级、软解、错误提示沿用现有位置与文案，只调整为不被新控制层遮挡。

## 6. 测试与验证

- JVM 单测：`remoteSeekStep`、`scrubTarget`、`remoteAction`、选项选择逻辑。
- 手势与焦点没有自动化测试（沿用 ADR-0041 的做法）：更新 `android/README.md` 的真机检查清单。
- 交付前在手机模拟器 `yb_test` 与电视模拟器 `yb_tv` 上实际操作并截图；注意模拟器是软件渲染，且 10-bit HEVC 硬解会失败，测播放用 8-bit H.264。

## 7. 决策记录

实现落地后新增 ADR-0056，标明取代 ADR-0041 的控制层与遥控器部分（背景、决策、后果、否决方案）；ADR-0041 状态改为“部分取代”。

## 8. 否决方案

- **只修电视焦点与手机手势**：不动结构，观感提升有限，达不到 Infuse 的整体感。
- **一次做选集、章节、缩略图**：要先补后端数据，工期长，放第二阶段。
