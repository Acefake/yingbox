# 自动追更以网盘转存为主流程

状态：已批准，2026-11-06 用户授权全部实施。

## 目标

用户主动追一部剧后，系统将缺少的已播集转存到指定的 115 目录。没有本地文件夹、没有媒体库、没有挂载路径，也能完成追剧。播放记录不创建追剧任务。媒体库提供可选的本地查重与转存后入库能力。

## 当前依赖与问题

- `src/main/autograb/index.ts` 的 `trackOnline` 先调用 `calendar.ensureSeries`，必须在片库创建条目才能拿到任务使用的 `seriesId`。
- `placeholder-series.ts` 没有 TMDB 剧集库时抛错。这是内部数据模型的限制，不能作为用户使用网盘追剧的条件。
- `service.ts`、`backfill.ts` 从片库日历取得已播分集，转存记录也按片库条目 id 建键。
- `saver.ts` 将已转存后没有入库视为需要重试或提示的问题；纯网盘追剧不应进入这个分支。
- 前一轮新增的「先设置剧集媒体库」对话框会进一步固化错误前提，应随本次链路调整一起移除。

## 核心模型

追剧任务由自动追更模块持有，业务身份是 TMDB id。契约的 `seriesId` 是模块独立分配的不透明数字任务句柄；`libraryItemId` 才表示可选的片库关联。保留数字契约的传输形式，同时分开两种身份。

任务保存 TMDB id、标准剧名、原名、年份、海报、分类、追更方式、资源偏好、115 目标目录、分集信息及最近刷新时间。可选的 `libraryItemId` 仅指向媒体库中的同一部剧。

每集转存记录的键为 `任务句柄:season:episode`。已转存文件 id、目标 cid、撤销与跳过记录保留。转存状态和入库状态分别保存：网盘转存成功就是「已转存」；只有明确启用了媒体库关联，才另外显示「待入库 / 已入库 / 入库失败」。入库失败不撤销网盘转存成功，也不触发重复转存。

## 用户流程

1. 点「追更」后按剧名与年份匹配 TMDB，存在歧义时保留候选选择。
2. 确认剧集后创建或复用追剧任务。已配置的追更方式和剧集网盘目录直接复用；缺少配置时就地选择 115 目录和追更方式。
3. 开启后直接向 TMDB 获取正片季与分集信息，建立全部已播缺集记录。分集查询失败时保留任务并说明重试原因，不当作「没有缺集」。
4. 到点的缺集至少两集时先找合集；符合自动条件的候选优先转存，再补搜合集未覆盖的单集。继续按文件转存，只存缺少的集。
5. 在任务选定的 115 目录下按剧建立子目录；可配置剧集默认目录。库外任务的目录命名只依赖任务元数据与整理设置。
6. 配置媒体库关联时，可读取本地已有集数避免重复，并在转存后通知入库。库外任务不调用媒体库目标解析，也不因缺少库或挂载路径中断转存。
7. 取消追剧停止后续调度，移除该剧的追剧任务及关联追更记录，不保留「已取消」列表。已转存的网盘文件和独立的播放记录保留。重新追剧时作为新任务检查网盘已有文件，避免同名重复转存。

必要条件是可用的 115 登录、PanSou、网盘目标目录及剧集元数据服务。分别提示实际缺少的条件，不再提示用户先建媒体库。

## 接口与界面同步

- `autograb.trackOnline` 返回数字任务句柄 `seriesId`；侧板、单剧设置、合集进度和单集操作统一使用该身份。
- 从媒体库详情页追剧时，按该条目的 TMDB id 创建或关联同一个任务；`libraryItemId` 单独传递，不和任务身份混用。
- 日历按主动开启的任务展示在线追剧；观看进度只负责已看判定。片库日历上的追更标记通过关联关系映射到任务。
- 追更列表、海报、候选和目录信息直接来自任务元数据，不为展示它们要求媒体库存在。
- 自动追更页只展示在追任务及其待处理项，不展示「还有几部没追」「没在追的连载剧」或已取消任务。
- 新任务先编辑草稿，最终点「确认并开始追剧」才启动，关闭则取消草稿。首页按剧汇总合集匹配与缺集，提供「转存本剧缺集」，分集操作收在详情。
- 桌面与 Web/NAS 共用契约、服务和 Vue 界面。Android/TV 当前没有原生自动追更页面，本次不新增另一套追更实现。

## 旧数据迁移

状态升级到 v2，原始 v1 文件留备份。已知 TMDB id 的设置和分集记录按确定映射合并到同一个任务，保留模式、确认数、目录、转存文件、候选拉黑、跳过与撤销状态。

没有 TMDB id 的旧记录先尝试从原片库条目补齐；片库已不可用或身份有歧义时，记录保留为待确认身份，不自动猜测后启动。仅有播放历史不创建任务；旧的自动生成记录不能据此推断用户主动追剧。

迁移先生成完整新状态并原子保存，成功后才运行调度。重复启动不能重复迁移、重复建任务或重复转存。原片库占位条目不自动删除，也不再作为追更启动的必要步骤。

## 验证

- 媒体库数量为零：选定 115 目录后能建立任务、读取分集、优先匹配合集、转存并补搜缺集。
- 纯网盘模式：转存成功后无「未入库一小时」错误，不继续尝试媒体库通知。
- 媒体库离线：库外任务正常转存；明确启用关联的任务独立显示入库状态。
- 已在网盘保存的文件、已入库的集与历史转存记录能查重；重启和旧数据迁移不重复转存。
- 不追、跳过、暂停、空间不足、确认门槛、限额、单飞及撤销校验保持有效。
- 不确定的旧剧身份不会自动启用；只有播放记录时日历与追更列表均不新增任务。
- 组件验证覆盖没有媒体库时的目标目录选择、任务开启与取消，以及分集和转存状态展示。

## 决策记录

实施时新增 ADR，取代 ADR-0049 中「在片库建占位条目作为在线追更前提」的决策，并调整 ADR-0029 的身份与目标目录说明；保留 ADR-0050 的合集优先与只转存缺集规则。

不采用自动创建隐藏媒体库的方案：它仍使追剧身份、分集和成功状态依赖媒体库，无法满足媒体库完全缺失或不可用时的网盘追剧需求。
