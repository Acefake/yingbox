# ADR-0036 安卓在线源自动启停：服务启动先体检，通的启用、不通的停用

- 日期：2026-11-03
- 状态：已采纳
- 相关：ADR-0032（选源）、ADR-0035（测速排序）

## 背景

选源和搜索会请求全部站点，坏站点多时要等它们超时，还有只会返回广告的垃圾源。桌面端用「启动轮次」管理：
每次启动对全部源跑一遍（`use-source-refresh.ts` 的 `checkAll(startup)`），通的启用、不通的关掉，之后只用启用的。

## 决策

1. **服务启动后在后台跑一轮体检**（`src/server/view/source-health.ts`），手动「重新检测」复用同一逻辑。
   规则与桌面一致：CMS 取第一页列表（8 秒超时，响应有 `list` 数组才算通）；插件后台搜一次「电影」（45 秒超时，
   熔断或没有 `list` 才算不通，空列表算通）；成人源不参与；同时 6 个。
2. **三态**：通、不通、不知道。引擎暂时不可用（调用本身抛错）是「不知道」，保留原状态，不因为引擎没起来就把源全关了。
   没检测过的源按启用算，第一轮没跑完时不挡搜索。
3. **结果持久化**在 `user_state`（键 `online_source_health`，站点名 → 是否通），重启后立刻沿用上次判断，新一轮再更新。
4. **停用的源在三处被跳过**：搜索（`view.search`）、选源（会话结果和请求的站点清单）、自动换源（备用线路来自选源结果）。
   用户在详情页手动点「不再使用」的站点（`view.blockSite`，键 `online_blocked_sites`）与体检停用合并处理，手动屏蔽的可在设置里恢复。
5. **设置页「数据源」**：检测进度、已停用的站点、重新检测、手动屏蔽的站点与恢复。`view.sourceHealth` / `view.recheckSources`。

## 后果

- 第一次启动约 40 秒跑完 57 个源（实测 17 个不通被停用）；跑的过程中选源仍可用。
- 站点只在下一轮体检时才会「复活」；暂时抖动的站点会被停用到下次检测，手动「重新检测」可以立刻再测。
- 体检会对每个站点各发一次请求（插件要一次搜索），流量由并发上限约束，每次服务启动一轮。
- 垃圾源（能正常返回、内容是广告）体检发现不了，靠手动「不再使用」。

## 否决方案

- **只在用户点开某站点时才检测**：搜索要先知道哪些可用，等于没有。
- **安卓端自己检测**：要在 Kotlin 里重写插件调用与判定，且手机在后台会被杀。
