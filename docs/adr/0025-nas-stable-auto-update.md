# ADR-0025 NAS 跟随稳定版自动更新

- 日期：2026-10-30
- 状态：已采纳
- 局部取代 ADR-0024 中默认固定版本、用户手动切换版本的部署方式。

## 背景

NAS 用户要求自动接收稳定版，不愿每次修改镜像版本号。Docker 重启策略不会拉取新版镜像，影盒现有 Electron 更新器也不能更新 NAS 容器。用户同时要求在本机构建发布，不使用 GitHub Actions。

## 决策

NAS Compose 默认使用公开的 `ghcr.io/acefake/yingbox-nas:stable`。每个应用版本保留独立标签。本机发布工具先锁定版本索引摘要，验证 amd64、arm64 的健康状态、运行身份和 NAS 接口，再提升稳定标签。首次 stable 复用已发布的 `1.0.0-nas.1` 应用镜像。

Compose 增加固定版本和索引摘要的 Watchtower 更新服务，每天北京时间 04:00 检查。用容器名 `yingbox-nas`、显式 enable 标签和专属 scope 共同筛选，仅更新影盒；不更新自身，不启动停止的容器，不清理旧镜像或卷。更新服务不给宿主公开管理端口。

仅更新服务挂载 Docker socket；影盒应用不获得 Docker 管理权限。筛选规则属于行为约束，不能当作安全隔离。更新服务可以管理 Docker，部署文档必须说明这一权限。更新时保留原挂载和参数，停止等待为 60 秒。

配置目录和数据库沿用现有挂载，容器被替换后仍可读取。已有安装只需替换一次 Compose 并使用 stable；自定义挂载不能被默认目录覆盖。允许暂停更新服务或指定具体版本，保留人工回退能力。Windows 发行与更新配置保持不变。

## 后果

用户不用逐次改版本号，但 NAS 需要能够访问 GHCR。拉取失败时保留当前容器，下次重试。实际替换会短暂中断网页和播放，新版异常时需要根据健康状态和日志人工处理。

本方案不实现自动回退，也不保证新数据库能被旧版读取。发布涉及迁移的应用版本前，维护者必须验证兼容性和备份恢复；NAS 配置需要定期备份。Watchtower 自身固定摘要，升级由维护者更新部署包并验证。

## 否决方案

- 只使用 stable 标签：仅改变标签不会让运行中的容器更新。
- 依赖 NAS 计划任务：不同设备需要不同的任务配置和权限操作。
- 让影盒网页直接管理 Docker：扩大面向用户的服务权限，增加更新接口和故障恢复逻辑。
- 跟随未验证的开发镜像：会把构建或单架构故障直接推送给自动更新用户。
