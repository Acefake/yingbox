# ADR-0023 NAS 直播与入库推送

- 状态：已采纳

日期：2026-10-28。部分取代 ADR-0020「入库推送仍只在桌面端」的限制。

## 背景

NAS 的网页端需要访问直播源、节目单与网盘，并在无人打开页面时发送入库通知。

## 决策

- 通用 HTTP 域路由由服务入口统一登记，网盘关闭时直播与通知接口仍可用；未启用的域按既有线格式返回失败。
- NAS 实现 iptv 的远程播放列表、线路探测和 XMLTV 方法，复用现有解析与缓存。逐跳目标校验与播放代理共用 `YINGBOX_STREAM_ALLOW_PRIVATE` 白名单；不开放任意服务器文件读取。本地文件对话框仅在桌面端显示。
- 网页直播经已有 `/api/stream` 播放代理，媒体请求不依赖浏览器跨域访问上游。
- NAS 复用推送服务发送 Bark / Telegram。普通设置在 server-settings.json，密钥在权限 0600 的 secrets.json；接口只返回是否配置，密钥可写可清除但不回显。
- 新电影、新剧集与追更入库进入同一去重、类型过滤和合并流程。NAS 不提供系统通知；自动字幕仍由服务端环境变量配置。

## 后果

NAS 可独立执行入库推送。浏览器直播仍受解码能力限制，不增加转码或 UDP/RTP 支持。直播源与频道收藏保留浏览器本地存储。

## 否决方案

- 让浏览器直接抓直播源和发送渠道密钥：跨域不稳定、网页关闭后无法推送。
- 在 NAS 引入 Electron：违反纯 Node 服务部署约束。
