# ADR-0051 按设备选择网络端点与多镜像回退

- 日期：2026-11-06
- 状态：已采纳
- 扩展：ADR-0046，取代其中固定单镜像及 429 换源规则。

## 背景

GitHub 更新和插件资源需要多候选；TMDB 主 API 在部分网络不可达，但备用域名可能可达。桌面、NAS 与 Android 的出站环境不同，检测结果不能跨设备通用。

## 决策

- 网络配置为 `network.optimization`，桌面由主进程保存，Web 由服务端保存，Android 后台请求由内嵌服务保存，原生 APK 下载另存本机副本。
- GitHub 官方优先；公开文件允许有序 HTTPS 镜像，API 仅使用已验证支持该能力的内置端点。凭据请求不自动送公共镜像。
- TMDB 主 API 与 api.tmdb.org 之间仅对 GET 网络错误和 5xx 回退；鉴权、权限、429 和外部取消不切换。URL 保留路径和查询。
- 公网目标及每次重定向继续执行现有 SSRF 校验；跨源重定向清除 Authorization、Cookie。测试使用固定公开样本，不发送用户 Token。
- 不修改系统 hosts、DNS、Docker daemon 或发布凭据。高级代理、应用内 DNS 与 NAS 第二发布仓库独立交付。

## 后果

设置保存后新请求读取当前配置，缓存内容仍可复用。设置页显示具体能力与检测范围，不能把 API 可达标为凭据有效。公共端点无长期 SLA，目标设备仍需真实验收。

## 否决方案

- 所有请求强制走同一镜像：会影响视频、115 与局域网，并混淆 API 和文件下载能力。
- 内置固定 TMDB IP 或发布本机合成 DNS 地址：缺少稳定性和跨设备有效性证据。
- 自动修改 Docker 并重启：超出应用内出站策略范围，影响宿主机其他容器。
