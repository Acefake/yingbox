# ADR-0018 桌面端内置播放器改为独立窗口

- 状态：已采纳（2026-10-26）
- 相关：取代 ADR-0015 里「桌面端也用应用内播放弹窗、角落小窗、不开独立窗口」的部分；网页端仍是 ADR-0015 的播放层

## 背景

ADR-0015 让桌面与网页共用一个盖在主窗口上的播放弹窗，靠角落小窗回到页面。用户要求播放器是单独的窗口：看片时主窗口照常浏览，播放窗口可以单独放到副屏、调大小、置顶。

## 决策

- 主进程 `src/main/player-window/`：单例播放器窗口。没开就创建，开着就换片并聚焦；无边框、黑底，窗口键与主窗口同一套（`WinControls`）；全屏用页面的 HTML 全屏，Esc 退出；置顶跟设置 `player.windowOnTop`（控制栏图钉 / 快捷键 I 与设置页同一个开关）；关窗时把位置与大小记进设置 `player.windowBounds`，下次沿用，不在任何屏幕上时回到主屏居中（`bounds.ts`）。关窗即停止播放；主窗口关闭时一起关。
- 安全：沿用 `window-security`（禁导航、外链交系统浏览器）、会话级 CSP（含 `yingbox-stream:`）；播放器窗口与主窗口共用 preload，但主进程给它加启动参数 `--yingbox-player-window`，preload 据此只暴露播放会话用到的域（`shared/player-window.ts` 的 `PLAYER_WINDOW_DOMAINS`），没有片库、下载、网盘等主窗口能力（拆成两个 preload 入口会打包出共享 chunk，sandboxed preload 加载不了）。
- 渲染层：独立入口 `player.html` → `src/player.ts` 挂 `PlayerWindowApp`，不带路由、外壳与 AI 助手。播放台 `features/player/stage/PlayerStage.vue`（玻璃顶栏 + 播放会话）由播放器窗口与网页端播放层共用。
- IPC（契约 `playerWindow`）：主窗口 `open(payload)` 把载荷交给播放器窗口（转成普通 JSON；媒体库条目带上片库记的续播位置 `libraryResume`，播放器窗口里没有片库缓存）；播放器窗口 `ready()` 取走就绪前的载荷，之后换片走 `play` 事件。调用方在主进程校验：`open` / `command` 只认主窗口，其余只认播放器窗口。
- 进度回写：播放会话的写入统一成进度事件（`progress/progress-events.ts`：save / finish / continue / flush）。网页端就地写；播放器窗口把事件经主进程转给主窗口，主窗口照同一个 `applyProgressEvent` 写进片库进度缓存、本地进度表、「已看完」、继续播放，「想看」自动移出等订阅也都在主窗口，界面立即更新；无痕模式在写入端判断。
- 遥控与在播状态：播放器窗口在遥控目标变化时、播放中每 2 秒把在播状态（片名、私密、能否遥控、问剧情、播到哪）报给主窗口；AI 助手的命令与问剧情经主进程转给播放器窗口执行并回执（5 秒没回按失败）。助手不再有「播放器在前台」的桌面模式（只剩网页端播放层）。
- 托盘 / 媒体键的命令发给正在报状态的那个窗口（播放器窗口，或跟着 mpv 的主窗口）。
- 播完提示里的应用内地址（如「去追更」）交给主窗口打开并把它带到前面。
- 删除：角落小窗（`mini/`、设置 `ui.miniPlayer`、播放器的 `compact` 收敛逻辑）、桌面端的应用内播放弹窗路径（`modal/player-modal.ts`、切路由自动缩小）。网页端没有窗口可开，`modal/PlayerModal.vue` 只剩网页端播放层。直播页的页内播放区不变。

## 后果

- 主窗口与播放器窗口共享同一个会话与 localStorage；读续播进度可以直接读，写一律经主窗口，主窗口的状态不会和存储不一致。
- 关掉播放器窗口时最后不到 2 秒的进度靠页面 `beforeunload` 发出的事件（flush 直接读视频元素的位置，刚拖动完就关也不丢；Electron 实测关窗时这条 IPC 能送到主窗口）；整个应用退出时两个窗口同时卸载，这一段可能丢。
- 网页端行为不变（盖在页面上的播放层，只是没有了小窗）。

## 否决方案

- 保留主窗口内的播放层、加「弹出」按钮：两套播放界面并存，用户要的是默认独立窗口。
- 播放器窗口自己写片库进度：主窗口的片库进度缓存与继续播放横排不会实时更新，还得再做一层跨窗口同步。
