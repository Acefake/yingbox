# ADR-0037 安卓发布与应用内更新

- 日期：2026-11-03
- 状态：已采纳
- 备注：发布方式、标签分类和取包规则已由 [ADR-0038](0038-unified-github-release.md) 取代；「不默认引入第三方下载代理」已由 [ADR-0046](0046-update-mirror-fallback.md) 部分取代

## 背景

手机和电视共用原生应用，需要独立版本、固定签名和可在遥控器上操作的更新入口。桌面更新使用 GitHub 的 Latest，安卓发布不能替换它。

## 决策

1. 本机构建发布，不增加 GitHub Actions。`android/version.properties` 保存 `versionName=x.y.z`，`versionCode=x*10000+y*100+z`；y/z 为 0–99，x 不超过 214747。手机和电视共用包名、签名及 APK，按 arm64-v8a、x86_64 分包。
2. GitHub Releases 使用 `android-vX.Y.Z` 标签、Pre-release 分类及 `latest=false`。资产命名为 `yingbox-android-X.Y.Z-<abi>.apk`，同时发布 SHA-256 清单。分类用于与桌面发布隔离，应用更新器会检查这些安卓版本。
3. 发布签名从被忽略的 `android/keystore.properties` 读取，密钥保存在仓库外。发布任务缺少签名时失败，不能退回调试签名。后续覆盖更新必须继续使用同一签名。
4. `view.appUpdate(current, abis)` 查询发布列表，缓存十分钟，并发请求复用。只返回版本、文件名、ABI、大小和 SHA-256 均有效的新包。失败不缓存成功结果。
5. 应用启动在距上次成功查询六小时后静默检查；失败不弹窗。设置的「关于」支持主动检查。发现新版后可下载，大小和 SHA-256 均通过后才交给系统安装器；全程 HTTPS，重定向逐跳检查。
6. 不静默安装、不绕过系统确认。Android 8 及以上缺少安装权限时打开系统授权页，返回后复用已下载的包。取消安装后可再次打开安装器。对话框隔离手机触摸及电视焦点，返回键只关闭提示。

## 后果

- 密钥与 `keystore.properties` 必须在可信位置单独备份；丢失签名后无法对已发布应用覆盖更新。
- 先前调试签名的测试包不能直接覆盖为正式签名。正式版本之间保持签名和递增版本码。
- GitHub 无法连接时的检查与下载回退见 [ADR-0046](0046-update-mirror-fallback.md)。
- arm64 真机和杜比视界的能力不由 x86_64 模拟器验证替代。

## 否决方案

- 将安卓发布标为 Latest：会干扰桌面更新源。
- 使用调试密钥发版：签名保管和后续更新不可控。
- 静默覆盖安装：普通应用没有该能力，且不应绕过设备所有者确认。

发布操作见 [安卓发版指南](../android/android-release.md)。
