# ADR-0006 下载断点续传、任务记目录、7 天孤儿临时文件清扫

- 状态：已采纳（2026-10-22）
- 相关：PR #58、#65

## 背景

下载中断（崩溃、退出、引擎空闲退出）后旧实现从 0 重下。续传又带来新问题：中途改下载目录后旧目录的临时文件找不到，失败任务的临时文件一直占盘。

## 决策

- 续传：HLS 写 `.partial` 加 `.partial.segs`（清单指纹 + 每单元「序号 字节数 sha1」，先写数据后记账），重启时重算校验、截断到最后完好的单元；直链写 `.partial.json`（ETag / Last-Modified / 长度），用 `Range` + `If-Range` 续，200 或 `Content-Range` 不符就从头。
- 任务记目录：`DownloadTask.dir` 在第一次开始时定下并持久化；重试、续下、移除清理都用它。已开始的失败任务重试仍用旧目录以便续传，只有从未开始的任务跟随新设置。
- 清扫：引擎启动加载队列后扫当前目录与各任务目录，只删名称合法的任务子目录里不属于任何等待 / 进行中任务、且 7 天未修改的 `.partial[.segs|.json]` 临时文件。失败与取消保留临时文件，移除任务时删除。

## 后果

- 续传后产物与一次下完的哈希一致（SIGKILL 端到端验证）。
- 改目录后，已开始的任务仍写旧目录，这是为了能续传而接受的取舍。
- 失败任务的临时文件最多占盘 7 天（或直到重试 / 移除）。

## 否决方案

- 失败即删临时文件：失去续传。
- 立即清扫所有不属于任务的临时文件：会误删正在被另一次启动使用、或用户刚手动挪回的文件；7 天是宽限。
- 改目录时迁移已开始任务的临时文件：跨盘移动大文件慢且可能失败，收益只是目录整齐。
