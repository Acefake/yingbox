# ADR-0049 在线剧追更：片库里的占位剧条目

- 日期：2026-11-05
- 状态：已被 ADR-0052 取代
- 补充：[ADR-0029](0029-autograb-target-and-organize-home.md) 追更按片库剧条目 id 工作；设计见 `docs/s-atlas/specs/2026-11-05-online-series-autograb-design.md`

## 背景

追更的 `seriesId` 是片库剧条目 id，播出表来自片库日历。继续播放里的在线剧不在片库，追剧日历「在线追剧」一排因此没有追更入口。
片库此前没有「没有文件的剧条目」：回收任务（`GC_SQL`）会删掉没有文件的未锁定条目。

## 决策

1. 点「追更」时用剧名（或用户选的候选）匹配 TMDB，在片库建**占位剧条目**：`type=series`，`local_key=placeholder:tmdb:<id>`，`match_state=locked`，
   放在第一个 TMDB 剧集库，没有文件。不加列、不迁移；`locked` 让它躲过回收，`local_key` 唯一让创建幂等。
2. 占位条目按 `merge_key` 与之后入库的真实条目合并，追更 `seriesId` 不变。同 TMDB id 已有真实条目时直接用它，不建占位。
3. 海报墙查询排除占位条目；版本成员排除占位。日历、追更、条目详情照常可见。
4. 渲染层在内存里记在线记录 → 片库剧 id 的映射（不落盘），重启后按剧名相同对应，用来在日历里去重和显示「追更中」。

5. 追更要存整部剧：建好条目后登记「存整部剧」（`state.backfill`），开始追更的第一轮用 `calendar.seriesEpisodes` 取到今天为止播出过的全部集，把缺的都建成记录；
   平时的日历只往回看 14 天，会漏掉更早播出的集（如第 1 集）。

## 后果

- 片库里会留下用户看不到的空条目；停止追更不删它（再追复用）。清理列为后续。
- 依赖「存在剧集库」；没有时提示先添加。
- 占位条目的 `local_key` 前缀成为约定，查询里按前缀过滤。

## 否决方案

- **追更改按 TMDB id 工作**：要改 `seriesId` 语义、状态文件、侧板和日历，波及面远大于一个占位条目。
- **加 `placeholder` 列**：迁移版本号与别的会话冲突，降级被拒；前缀约定足够。
- **在线剧自己建一套追更**：转存位置、入库、洗版都要重做一遍。
