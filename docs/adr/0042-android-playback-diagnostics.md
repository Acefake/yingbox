# ADR-0042 安卓播放诊断：输入格式、能力与最终输出分开

- 日期：2026-11-04
- 状态：已采纳
- 部分取代：ADR-0039 的决策提示与能力缓存、ADR-0041 的统计信息展示位置

## 背景

播放器从编码串获知 DV profile，但没有基础层兼容 ID，也没有最终屏幕输出模式的可靠证明。播放建议没有执行转换，提示“已按 HDR10/SDR 播放”会让人误以为转换已成功。进程级能力缓存无法反映 HDMI 与音频路由变化。

## 决策

1. 缺失传递函数时保留未知，不能默认 SDR。DV MIME 能确认片源类型，但不能补出未知 profile。
2. DV 原生播放候选同时检查硬件解码 profile 和显示 DV 能力。这里只判断动态范围兼容性；尺寸、帧率和 codec level 支持继续交给 Media3，不能据此宣称最终输出成功。
3. 缺少对应 DV 解码器时，P5 提示颜色风险，其他 profile 提示兼容层未确认。屏幕能力不足提示映射未确认。不执行新的转码或伪造 codec 参数。
4. 播放画面监听显示与音频设备变化，重新读取能力；离开时注销监听。能力更新不重建播放器。
5. 右上角徽标明确标为“片源”，跟随视频输入格式和音频输入格式变化，随控制层显隐。它不表示屏幕已进入对应模式。
6. 统计整合到播放设置的诊断区，避免和右上角片源标识重叠；支持复制结构化报告，不附带媒体地址、标题、路径和异常原文。报告明确最终输出模式未确认。

## 后果

- 安卓手机与 Android TV、在线与 NAS 片库共用实现。
- HDR10+ 输入动态元数据识别、基础层兼容 ID、实际输出证明、DV 重建与超分仍按分阶段方案推进，不能由这一批诊断改动宣称支持。
- 暂无连接的真机，HDR/DV 输出、HDMI 热插拔、控件布局及遥控器操作需要实机验收；JVM 测试和 APK 构建只能证明逻辑与构建结果。

## 否决方案

- 根据显示器支持 HDR10 就宣称 DV 已转为 HDR10：没有转换执行或输出证据。
- 根据放大后的帧尺寸标原生 4K：混淆片源与增强结果。
- 继续全局缓存显示能力：换显示器后容易沿用失效结论。
