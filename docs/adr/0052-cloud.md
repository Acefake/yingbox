# ADR-0052 网盘追剧独立于媒体库

- 日期：2026-11-06
- 状态：已采纳
- 取代：[ADR-0049](0049-online-series-placeholder.md) 的占位剧前提；补充 [ADR-0029](0029-autograb-target-and-organize-home.md) 的可选媒体库关联边界。

## 背景

自动追更的输出是115网盘文件，媒体库用于可选查重和入库。把片库条目id用作追剧身份，会导致没有媒体库时无法追剧；媒体库重建还会改变或复用条目id。取消后保留未追推荐卡片，也不符合用户只管理主动追剧任务的意图。

## 决策

1. 追剧模块直接匹配TMDB并读取分集，任务、分集与网盘转存状态存于`autograb.json` v2，不创建片库占位。TMDB id是剧集业务身份，`seriesId`是追剧模块分配的不透明数字句柄，`libraryItemId`仅表示可选关联。
2. 全局方式只作用于主动创建的任务，不根据播放记录或媒体库在播列表创建任务。任务海报、名称、年份和分类来自独立元数据。
3. 目标是任务选定的115目录或分类/剧集默认目录。关联媒体库时可沿用已有网盘目录，使用关联前核验TMDB身份；媒体库数字id不能跨身份使用。
4. 保留ADR-0050：缺多集先找合集，只转存缺少的文件，优先转存合集候选，再补搜遗漏的单集。沿用限额、空间检查、单飞、文件同名检查和撤销校验。
5. 纯网盘转存成功就是「已转存」。媒体库关联与同步分别记录，入库错误使用独立的`libraryError`，不改写转存成功。任务标记与媒体库标记使用不同命名空间，入库通知转换为媒体库身份。
6. 取消移除任务、分集、补全集队列和内存进度，不删除已转存文件或播放记录。正在查找、排队转存的结果必须复核任务存在性。页面不展示未追及已取消任务。
7. v1迁移先保留原始备份，再原子保存v2；迁移失败不当作空状态覆盖。保留原任务句柄、目录、确认门槛、转存文件、跳过及禁止候选；同TMDB任务合并，按分集处理进度去重。无法确认的剧不猜测身份。
8. 新任务先是未启用的设置草稿。用户选好目录、方式和偏好，点「确认并开始追剧」后才获取缺集并开始搜索；关闭取消草稿。已启用任务的设置也在「保存设置」时统一保存。
9. 首页待处理列表按剧汇总合集匹配与缺集数量，「转存本剧缺集」统一操作本剧所有已匹配候选。分集选择、跳过和撤销收在详情中。底层仍逐文件查重、限速与转存，不整夹接收无关文件。

## 后果

- 零媒体库也能完成网盘追剧，桌面和Web/NAS使用同一服务及契约。
- 新任务的句柄不再等于媒体库条目id，所有媒体库调用和通知必须明确转换身份。
- 迁移备份提供回滚依据，当前任务状态不保留已取消记录；重新加入时核对网盘文件，避免同名重复转存。
- 片库历史占位仍可保留在库中，但不再作为追剧前置条件。

## 否决方案

- 自动创建隐藏媒体库：依然把网盘任务绑在片库身份和可用性上。
- 只删缺库提示：分集来源、目标目录和入库成功条件仍然依赖媒体库，问题没有解决。
- 用负数伪装库外条目：将两种身份塞进同一字段会扩大调用方误用风险；采用独立分配的任务句柄并显式保存关联。
