# ADR-0014 插件隔离与会话来源

- 状态：已采纳（2026-10-23）

## 背景

CatSpider 运行第三方脚本，需要解析 HTML、加解密、缓存与网络访问。直接在 Node 全局执行会让插件取得文件系统和原生网络权限。桌面播放器还需要跨域加载 HLS，网页片库可经 HTTPS 反向代理部署。

## 决策

- 每次插件动作创建独立 QuickJS WASM 上下文，不注入 Node 全局、模块加载器或原生网络；不以 `node:vm` 作为不可信代码的安全边界。
- 宿主桥只传 JSON、函数回调编号和不透明对象编号；禁止宿主原型、构造器与方法重绑定，Buffer 不暴露底层内存。HTML 仅提供 cheerio 的 `load`，不提供可自行联网的模块入口；CryptoJS 在解释器内运行。Buffer 仅提供受限创建接口。
- 插件总执行期限 30 秒，解释器内存 128 MiB、栈 512 KiB，宿主缓冲区累计最多 32 MiB、对象编号最多 50,000、定时器最多 1,000；结束后释放上下文、定时器并中止插件直连请求。
- 插件网络只经 SSRF 检查的宿主 API。安全策略拒绝不得回退到浏览器；代抓分区对请求、重定向与子资源同样检查公网目标。
- 桌面主窗口开启 `webSecurity`，禁止页面自行导航，系统浏览器只接收无凭据的 HTTP(S) 地址。HLS 经 `yingbox-stream` 专用协议转发公网 GET/HEAD 与 Range，不携带浏览器认证信息；相对地址以远端最终清单 URL 解析。
- 网页服务用 `--public-origin` / `YINGBOX_PUBLIC_ORIGIN` 显式指定 HTTPS 反代的公网源，据此写 `Secure` Cookie 并比较完整 Origin。不自动信任转发头，本地 HTTP 保持可用。

## 后果

- 增加固定版本的 `quickjs-emscripten` WASM 依赖，宿主仍按需加载 cheerio。插件编译、动作执行、Promise 微任务和结果序列化均受解释器期限限制。
- 依赖 Node 全局、宿主原型或超出限制的插件会明确失败，没有降级到 Node 执行的路径。
- 插件宿主 API 仍需独立审核；WASM 不代替网络策略，也不约束宿主库自身的实现缺陷。DNS 校验与实际连接之间的重绑定窗口仍属于现有网络层的限制。
- HTTPS 反代部署需要配置公网源并重新登录。本机 HTTP 不使用 Secure Cookie，Bearer 客户端沿用现有接口。

## 否决方案

- 隐藏 `process`、`require` 或用 `node:vm` 注入宿主函数：仍存在宿主对象越界风险，不能作为第三方代码隔离方案。
- 关闭全局浏览器安全检查以播放跨域 HLS：扩大页面权限，应由受限媒体传输入口解决。
- 自动信任 `X-Forwarded-Proto` / `X-Forwarded-Host`：后端可被直接访问时客户端能够伪造，应使用显式公网源配置。
