# ADR-0008 媒体库扫描按 16 ms 时间片让出

- 状态：已采纳（2026-10-22）
- 相关：PR #63

## 背景

`node:sqlite` 是同步 API。扫描原先每 2000 个文件一个事务后才让出一次，5 万文件冷扫时媒体库引擎的事件循环单次最长卡 405 ms（中位），查询和事件都被推迟。

## 决策

新增 / 变更按文件切片，移动与删除分片，空条目分块回收（每块 256 条），每片最长 `SCAN_SLICE_MS = 16` ms，片间让出事件循环；遍历时被删目录里的文件延后分片读取。`ScanOptions.batchSize` 换成 `sliceMs`。

## 后果

- 实测 5 万文件冷扫：最长卡顿中位 405 → 45 ms，超过 50 ms 的次数 27 → 0；删除 3 万文件最长卡顿 912 → 41 ms；CPU 多约 7%。
- 满载时单片偶尔 50–55 ms；刮削、整理、演员刷新仍按各自的批大小让出。

## 否决方案

- 固定条数分批：文件系统和磁盘速度差异大，条数管不住时长。
- 把写库挪到 worker 线程：改动大，且 SQLite 连接要跨线程协调；时间片已足够。
