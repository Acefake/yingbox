# ADR-0015 应用内播放弹窗：桌面与网页一套组件，可缩成角落小窗，不开独立窗口

- 状态：桌面端部分被 [ADR-0018](0018-player-window.md) 取代（2026-10-26：桌面端改为独立播放器窗口，角落小窗删除）；网页端播放层仍按本 ADR
- 相关：PR #108（feat/in-app-player）

## 背景

内置播放器先后有三套界面：桌面端盖满整个主窗口的播放层（不能进小窗，看片时没法回到页面）；网页端媒体库详情里的原生 `<video>` 播放层；在线详情等页面在非桌面环境下各自的页内播放层。小窗（`features/player/mini`）靠每个页面声明「宿主」、在离开详情时把播放器交出去，规则分散在各页面里，同一件事有好几份实现。

## 决策

- 只有一个播放界面：`features/player/modal/PlayerModal.vue`，应用根组件挂载一次，盖在当前页面上（遮罩 + 居中 16:9 卡片），页面状态不变。所有入口（媒体库详情、视频墙、在线 / 豆瓣详情、继续观看）都调 `openMediaPlayer`，桌面与网页走同一个组件；网页端媒体库把片库服务的流地址当作播放列表交进来。
- 关闭：Esc（走全局 Esc 层栈，输入法组字中不算）或关闭按钮；点遮罩不关，避免误触丢掉播放。播放会话卸载时保存进度、销毁 Artplayer 与 hls.js。
- 缩小：播放会话渲染在一个不归模板管的节点里（Teleport 目标），缩小时把这个节点整体搬进角落小窗，展开时搬回，播放器不重建、不重新请求；小窗里连播到下一集时只换小窗控制的 `<video>`。
- 切路由时弹窗自动缩成小窗，小窗跨路由保持、不自己展开；设置关掉小窗（`ui.miniPlayer`）时没有缩小按钮，切路由时弹窗保持。
- 不提供独立播放窗口（不恢复 `/player-popout` 与主进程播放窗口）；画中画用播放器控制条自带的按钮。mpv 外部播放不变。
- 弹窗与小窗用新层级 `--z-player`（6100），视频墙里点播放也盖在最上面。

## 后果

- 删除页面级的小窗宿主（`mini-host`）、播放器组件里的实例交接、网页端媒体库播放层与各页面的非桌面播放层；小窗只剩「弹窗交来的节点」一种来源。
- 网页端媒体库播放得到桌面同样的控制条、续播进度、字幕面板；浏览器不支持的格式显示播放器的错误面板。
- 页内播放层原有的「失败换同名其它来源」「列表下一部」只存在于非桌面兜底层，随之删除；桌面行为不变。
- 播放会话组件按需加载，首次播放时才下载 Artplayer / hls.js。

## 否决方案

- 恢复独立播放窗口并在弹窗里放「弹出」按钮：需要重新加回主进程窗口、IPC 契约与路由，用户确认不要。
- 保持盖满整个窗口：看片时无法回到页面浏览，和小窗的用途冲突。
- 继续由各页面做小窗宿主：规则分散、每个新入口都要重接一遍。
- 点遮罩关闭（其它浮层的惯例）：播放比其它浮层代价高，误触成本大。
