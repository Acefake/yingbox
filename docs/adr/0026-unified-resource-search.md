# ADR-0026 统一影片搜索与资源聚合

- 日期：2026-10-30
- 状态：已采纳

## 背景

搜索入口分别提供片库、在线源与 AI 对话，网盘检索另有页面。用户需要重复输入关键词，且浮层显示数量有限，同一影片的不同来源难以比较。

## 决策

- `/search?q=…` 是桌面和 NAS 共用的完整搜索页。浮层提供即时预览，普通回车提交完整搜索；用户显式选择结果后直接打开，问 AI 使用独立按钮或快捷键。
- search feature 编排现有片库、在线、PanSou、Torznab 接口，不增加后台聚合服务。取消后的会话不再发布迟到结果，失败与重试按来源隔离。
- 资源和作品分开建模。媒体类型和可信 TMDB ID 优先；无 ID 时片名、已知年份和类型必须一致。未知信息与手动拆分条目保留独立身份。115 按分享码、磁力按规范哈希去重。
- 片名、年份、季集和画质决定相关性；不能确认满足条件的结果标记为“可能相关”。未实际验证的在线、网盘、磁力资源明确标注，不承诺可播放。
- 初次查询直接返回可用结果；低覆盖时最多补查两个可信名称或 AI 解析的片名，同来源同词在会话中只发一次。片库每页 60 条，完整页可继续加载；其他来源展示接口已返回的所有条目。
- 桌面 AI 仅在提交搜索后解析条件并增强片库召回，失败保留普通搜索。NAS 使用构建适配器，不调用模型、不加载在线引擎，保持 ADR-0024 的产品边界。
- 资源面板复用播放、分享预览、转存目标与 115 离线下载；转存和离线下载仅在用户点击后执行。私密搜索保留本地范围，不跳转到外部资源聚合页。

## 后果

用户可以在一个页面比较同片资源，来源故障不会清空其他结果。元数据不足时可能展示独立候选，宁可保留候选也不误合并。别名补查可能增加至多两轮请求，受现有来源超时、并发和健康状态约束。

不新增数据库迁移、资源提供商、NAS AI 能力或向量数据库。现有资源页面仍可独立使用。

## 否决方案

- 只扩大浮层结果上限：仍需在多个页面重复检索，无法集中比较同片资源。
- 按片名直接合并所有结果：同名不同年或电影与剧集会被误合并。
- 由模型生成资源链接或宣称播放可用：无法追溯或验证来源。
- NAS 引入完整 AI 助手与在线引擎：超出本次范围，也不符合专用版的构建边界。
