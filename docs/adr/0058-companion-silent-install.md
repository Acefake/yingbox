# ADR-0058 独立更新窗口以命令行保持安装静默

- 日期：2026-11-07
- 状态：已采纳
- 部分取代：[ADR-0053](0053-update-restart-feedback.md) 决策 3 的静默标记。其余决策仍有效。

## 背景

独立更新窗口启动安装器时带有 `/S`，但安装脚本在更新并强制启动的路径上会执行 `SetSilent normal`，安装器自己的进度窗口会和等待窗口一起出现。`YINGBOX_UPDATE_UI=1` 写在子进程环境里，安装器提权后读不到这个变量，静默请求因此失效。等待旧进程退出也没有上限，旧进程不退出时窗口会一直停在安装阶段，安装器尚未启动。

## 决策

1. 独立更新窗口启动安装器时，在原有参数上附带 `--yingbox-update-ui`。安装脚本认出该标记后执行 `SetSilent silent`。没有该标记时，仍按 `YINGBOX_UPDATE_UI` 判断，普通安装向导和退出时的 `/S` 安装不变。
2. 等待窗口按阶段显示「正在退出旧版本」「正在安装更新」「正在启动影盒」。旧进程 30 秒内未退出则停止并显示原因，不启动安装器。安装失败不进入正在启动。
3. 更新窗口就绪后，主进程先走正常退出；15 秒内未退出则结束进程，避免等待窗口一直停在退出阶段。
4. 同一版本已准备过的更新运行时，之后只刷新窗口脚本，不重复复制渲染层。

## 后果

从尚不包含本决策的已安装版本做应用内更新时，运行中的仍是旧更新窗口，不会附带 `--yingbox-update-ui`。这一跳仍可能出现安装器窗口。用户需要先安装包含本决策的版本，之后的应用内更新才同时具备超时、强制退出和命令行静默。

等待窗口会记录退出与安装耗时，便于区分卡在退出还是卡在安装。

## 否决方案

- 只继续依赖 `YINGBOX_UPDATE_UI`：提权后的安装进程读不到该变量，无法保证静默。
- 旧进程不退出时仍启动安装器：安装目录被占用，安装会失败或看起来长时间无进度。
- 用 `app.exit` 代替正常退出：会跳过退出事件上的收尾。强制结束只作为正常退出超时后的兜底。
