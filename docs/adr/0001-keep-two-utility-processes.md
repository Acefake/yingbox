# ADR-0001 两个 utilityProcess 不合并

- 状态：已采纳（2026-10-22）
- 相关：PR #61、#62、#64（数字为 Electron 37.10.3 实测）

## 背景

桌面端有两个 utilityProcess：后台引擎（在线源 / CatSpider 插件、MissAV、HLS 下载）与媒体库引擎（扫描、识别刮削、写出、`node:sqlite`）。两套宿主和线协议几乎同形，有人提议合成一个进程省内存。

## 决策

保留两个进程，只合并宿主层：主进程共用 `UtilityHost`（`src/main/utility/host.ts`），两个子进程说同一套线协议（见 ADR-0009）。

## 后果

- 媒体库冷扫、同步 SQLite 写库、第三方插件的死循环或崩溃，只影响各自进程；下载不会因媒体库崩溃中断。
- 多付约 38 MB 私有内存（一个空 utilityProcess ≈18 MB + 第二份 cheerio ≈20 MB）。cheerio 按需加载（#57）和后台引擎空闲退出（ADR-0007）已把空闲时的这笔开销基本收回。
- 满足以下三条才值得重新评估：真机测出每个进程私有内存远超 18 MB 且目标设备内存很紧；媒体库写路径全部异步化、事件循环不再卡；CatSpider 插件改在隔离环境里执行。

## 否决方案

- 全合并成一个进程：只省 ≈38 MB 和约 0.4 s 启动 CPU；实测 5 万文件冷扫会让同进程事件循环单次卡 300–450 ms，下载与在线解析跟着卡；任一崩溃会连带下载。改动 500–700 行。
- 维持两套宿主：留着「一件事两种做法」和媒体库引擎重启后事件订阅丢失的缺陷（#53 已修）。
- 把 CatSpider 插件再拆一个进程：暂不需要，插件来源变杂时再议。
