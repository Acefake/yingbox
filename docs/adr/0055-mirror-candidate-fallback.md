# ADR-0055 镜像候选的失败回退与内置镜像排序

- 日期：2026-11-06
- 状态：已采纳
- 扩展：[ADR-0051](0051-network.md) 的「鉴权、权限、429 不切换」；补充：[ADR-0046](0046-update-mirror-fallback.md) 的候选回退

## 背景

ADR-0051 落地为 `shouldTryNextMirror`：只有网络层失败和 5xx 才换下一个候选，其余 4xx 一律不切换。这条边界是为**官方端点**设的——401 / 403 / 429 说明本应用的鉴权或配额有问题，换源会掩盖真实原因。

但这条规则对**镜像候选**不成立。实测（2026-11-06）：公共反代 `https://gh-proxy.com/` 转发 GitHub API 时会间歇返回 `403`，响应头 `x-ratelimit-remaining: 0`。这是镜像自己的 GitHub token 配额耗尽，与请求方的鉴权无关。按原规则这个 403 不换源，检查更新直接失败并报「检查更新失败：HTTP 403」，而同一台机器上另一个镜像其实是通的。

同一轮实测的吞吐：`ghfast.top` 转发安装包约 1.76 MB/s，`gh-proxy.com` 约 173 KB/s，`ghproxy.net` 约 9 KB/s（实际不可用）。内置镜像顺序沿用了更早的探测结果，把最慢的放在后面、把已不可用的留在列表里。

## 决策

1. **区分官方候选与镜像候选**。候选列表仍是官方在前、镜像按配置顺序在后。`shouldTryNextMirror` 增加 `viaMirror` 参数：官方候选（列表第 0 位）的判定完全不变，429 与其它 4xx 仍不切换，保持 ADR-0051 的鉴权、权限边界。
2. **镜像候选返回任何非 2xx 都换下一个候选**。镜像的 403 / 404 / 429 说明这个反代自身不可用（配额耗尽、路径不支持），与本应用的鉴权无关；网络层失败和 5xx 原本就换源。镜像候选的判断不再复用官方端点的状态码语义。
3. **内置镜像按实测吞吐排序**。安装包下载候选为官方、`https://ghfast.top/`、`https://gh-proxy.com/`；移除实测不可用的 `https://ghproxy.net/`。GitHub API 仍只使用已验证支持该能力的 `https://gh-proxy.com/`（沿用 ADR-0051「API 仅使用已验证支持该能力的端点」）。用户自定义的镜像与排序照旧生效。
4. **保存过早期内置列表的配置跟随当前内置列表**。解析网络配置时，如果镜像列表与早期内置值完全相同（用户没增删过），按当前内置列表处理；用户自己增删过的列表保持原样，不做迁移。
5. **低速候选可放弃**。安装包下载在**还有下一个候选**时，统计窗口内的平均速率低于阈值就中断当前候选、换下一个；最后一个候选不因速度被中断，避免慢速但可用的网络被直接判死。阈值按实测的可用速率与不可用速率之间的区间选取。

## 后果

- 镜像自身故障（配额耗尽）不再表现为「更新失败」，而是自动切到下一个候选。
- 官方候选的 4xx 语义没变，不会把鉴权失败或限流误判成网络问题。
- 镜像候选的 4xx 被当作「这个镜像不可用」，镜像返回的真实业务错误信息不会展示给用户，只表现为换源后成功或全部候选耗尽。公共反代没有 SLA，这一取舍是为了可用性。
- 移除 `ghproxy.net` 只影响内置默认；曾手动添加过它的用户保留该项。
- 低速放弃会让慢速但最终能成功的候选在有备用候选时被提前放弃；最后一个候选不受影响。
- 保存过早期内置列表的用户，设置页会显示新的内置地址，而不是他们当初看到的那三条。

## 否决方案

- **把 4xx 一律改成可换源**：会破坏 ADR-0051 对官方端点的鉴权、权限边界；429 限流时也会被反复重试放大。
- **只靠网络层失败和 5xx 换源**：镜像的配额耗尽恰恰以 403 返回，实测会让检查更新直接失败，这正是本次要修的问题。
- **内置更多公共反代**：超时与攻击面增加，且只有实测通过的端点才应内置。
- **自建 CDN 或中转**：项目选择零运维（沿用 ADR-0046 的背景）。
- **改用 electron-updater 托管下载**：它同样直连 GitHub，不能解决镜像故障；ADR-0038 决策 5 与 ADR-0045 否决方案已记录相关取舍。
- **只调镜像顺序、不改回退规则**：顺序解决不了镜像中途开始返回 403 的情况。
