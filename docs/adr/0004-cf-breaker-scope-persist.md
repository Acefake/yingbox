# ADR-0004 Cloudflare 熔断按主机 + 用途、落盘、硬封锁不弹窗

- 状态：已采纳（2026-10-21 / 2026-10-22）
- 相关：PR #41、#55

## 背景

插件源被 Cloudflare 硬封锁（1020 / "Sorry, you have been blocked"）时，旧逻辑把封锁页当成可通过的挑战，主进程把代抓窗口显示到右下角等 20–30 秒，而且每次搜索都重来。熔断只按主机算、只在内存里，一个站搜索被封会连带分类也停，重启后又从头撞一遍。

## 决策

- `src/shared/net/cf-page.ts` 把页面分为 ok / challenge / blocked，封锁优先；硬封锁立即熔断，从不显示窗口（窗口在挑战途中跳到封锁页也立即销毁）。
- 熔断键是主机 + 用途（pathScope：search / browse，按地址判断）；连续 3 次失败也熔断，冷却 30 分钟，可一键重置。番号刮削仍按主机。
- 引擎熔断状态写入 `userData/online/breaker.json`，重启后仍生效。

## 后果

- 被封的源在搜索中被跳过并标红写原因，分类浏览不受搜索被封影响。
- 同一出口频繁撞挑战会被升级成必须人工点击的 Turnstile，所以熔断宁可保守。
- 熔断误判会让一个源停 30 分钟，用户可在数据源面板重试或一键更新解除。

## 否决方案

- 只按主机熔断：#41 的实现，搜索被封连带分类也停。
- 只在内存里记：重启后每个被封的源再撞一次。
- 硬封锁也弹窗让用户点：封锁页没有可通过的挑战，弹窗只是打扰。
