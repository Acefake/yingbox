# ADR-0044 mpv 超分：独立滤镜、按 SDR 和显示需求启用、配置状态与效果分开

- 日期：2026-11-04
- 状态：已采纳
- 相关：ADR-0016、HDR/DV 与全端增强分阶段方案

## 背景

原有超分开关根据片源高度挂载 `d3d11vpp`，使用 `vf set` 替换整条链，且按输入乘二展示输出尺寸。它没有区分 HDR、未知格式、显示需求和驱动侧实际效果，并发开关或换片也可能留下旧状态。

## 决策

1. `mpv-enhancement.ts` 负责规则和串行滤镜生命周期。观察 `video-dec-params`、`video-out-params`、`osd-dimensions`、`hwdec-current` 与 `vf`，输入和输出尺寸分开。
2. 仅在 Windows、枚举到 NVIDIA GPU、当前 D3D11 硬解、已确认 BT.709 SDR、片源低于 1920×1080 档位且实际需要放大时尝试配置。GPU 枚举不证明 mpv 使用该设备；驱动与 GPU 是否真正执行 AI 增强仍未确认。
3. 影盒只添加或移除 `@yingbox-vsr` 命名滤镜，不替换整条滤镜链。受控换片先挂起更新并等待清理，旧片源 refresh 和属性不能重新挂载；进程与媒体代数使迟到响应失效。
4. 状态分为关闭、等待、不支持、旁路、已配置、失败。滤镜存在只显示“已配置，AI 效果未验证”。尺寸来自实际滤镜输出，不计算或展示预测分辨率。
5. 失败后尝试移除自己的滤镜并暂停自动重试；用户切换开关或换片可重新评估。无法确认移除时报告失败，受控换片不能继续。
6. HDR、HLG、BT.2020 广色域和未确认色彩的片源旁路；同时检查所选视频轨的 DV profile 和 `dolbyvision` 色彩矩阵，使 DV 8.2 的 SDR 基础层也保持旁路。视频轨查询暂不可用时保留未知，元数据恢复后重新评估。高质量普通缩放仍沿用现有设置，不能标成 AI 超分。
7. 随进程加载 Lua `on_load` 钩子；启用受控握手后，钩子等待主进程挂起更新并排空旧命令，再同步清理标签并继续加载。清理失败或十秒未应答则 `stop` 后释放钩子，不启动受影响新片源，也不让加载永久挂起。`user-data/yingbox-vsr-hook` 确认脚本就绪，缺失时增强旁路。新文件 `file-loaded` 才解除挂起。
8. GPU 枚举只在请求超分时执行，最多等待两秒；查询失败保留未知，可在再次开关时重新探测。普通播放不等待 GPU 枚举。

## 后果

- `MpvStatus.vsr` 使用明确状态和原因，尺寸字段改为整条滤镜链的实际输出；调用方在同一轮迁移。
- 实际随包 mpv v0.41.0 提供 `d3d11vpp`。本机 AMD Radeon 780M 可以验证非 NVIDIA 路径和滤镜失败后的存活，无法验证 RTX AI 画质或 NVIDIA 性能。
- API 命令回执与滤镜列表不能证明 Tensor Core、驱动开关或实际画质效果。正向验证仍需支持的 NVIDIA 硬件。
- 目前不增加新 SDK、模型依赖、服务端超分或安卓帧处理路径。

## 否决方案

- `vf set` 整链替换：会移除用户其他滤镜。
- 输出尺寸等于输入乘二：与实际滤镜输出、最终窗口尺寸和 AI 是否执行没有必然关系。
- 在 HDR/DV 上直接叠加未经验证的处理：不能保证色彩与动态元数据正确。

## 依据

[mpv 官方手册](https://mpv.io/manual/stable/) 说明 `scaling-mode=nvidia` 只是启用对应扩展，实际效果依赖硬件及驱动设置；`video-out-params` 是滤镜链输出，并非最终窗口尺寸。
