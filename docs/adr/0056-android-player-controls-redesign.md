# ADR-0056 安卓播放控制层重构：手机 Infuse 式布局，电视只用遥控器

- 日期：2026-11-07
- 状态：已采纳
- 部分取代：ADR-0041 的控制层布局、手势范围与遥控器键位；ADR-0041 的沉浸式横屏、播放状态模型、手动换集等其余决策仍有效
- 相关：ADR-0039（播放内核）、ADR-0042（播放诊断）、ADR-0016 / ADR-0018（桌面播放器）

## 背景

ADR-0041 的控制层把所有入口堆在底部一条上：音轨、字幕、倍速、比例、全屏、诊断都要先点设置按钮，再在面板里找。手机上一只手换字幕要两步、还要在面板里认列表；电视上没有「拖进度」，只有左右键 ±10 秒，长片要按几百次。

遥控器的键位也随状态变味：同一个下键，有时把焦点送进控制层、有时打开设置面板；同一个确定键，有时按焦点上的按钮、有时是暂停；控制层显示时的左右键有时换按钮、有时快退快进。焦点在根容器和控制层之间来回跳，用户记不住自己的按键会做什么。

规格（`docs/s-atlas/specs/2026-11-07-android-player-redesign-design.md`）定的目标是：手机一只手就能唤出控制层、拖进度、换字幕 / 音轨 / 倍速，不进深层面板；电视只用方向键、确定键、返回键完成全部操作，每个键在同一状态下含义唯一、焦点始终可见。播放内核（`PlayerState`、解码与降级、轨道、画质增强、统计与诊断、续播与进度上报）不在范围内。

## 决策

1. **只重做控制层，内核一行不改。** `PlayerState` 仍是唯一状态来源，控制层只读它、通过回调修改；`PlayerHost(state, title, onPrevious, onNext, onBack)` 的签名与 `PlayerScreen` / `LibraryPlayerScreen` 的调用方式不变，新代码只新增文件。画面仍由 `PlayerView` 渲染，`useController = false`（ADR-0041 第 1 条）。

2. **手机布局按 Infuse 的 iOS 习惯。** 顶栏一行：圆形返回钮、两行标题（片名；集名小一号灰字，没有集名时不显示第二行）、右侧字幕 / 音轨 / 倍速 / 比例 / 画质增强图标，每个图标点开一个 `PhoneOptionsPopup` 小浮层，选完即关。中间三个大圆钮：快退 10 秒、播放 / 暂停（最大，72dp）、快进 10 秒。底部只有一条细进度：上一集、已播时间、4dp 高轨道，右端剩余时间（时长未知显示 `--:--`）、下一集；没有上一集或下一集时整个按钮不渲染、不占位。玻璃只给顶部按钮和中间圆钮，底部是渐变压暗（`Brush.verticalGradient`），不是整条玻璃。

3. **手机手势加一条横滑拖进度。** 横滑整屏宽度约等于片长的四分之一：`scrubTarget(startMs, dragPx, widthPx, durationMs)` 换算目标位置并钳制在 `0..duration`，屏幕中央显示「目标时间 (+差值)」，松手才 `seekTo`。时长未知（直播等）时横滑直接不响应，控件层也不会被钉住。单击显隐、双击左右半屏 ±10 秒、长按两倍速、左半屏竖滑亮度 / 右半屏竖滑音量沿用 ADR-0041，亮度仍然退出播放时还给系统。

4. **电视键位表是纯函数，三种模式每个键唯一含义。** `playback/engine/PlayerControl.kt` 里 `remoteAction(key, mode)` 返回 `TogglePlay` / `ShowControls` / `OpenPanel` / `ClosePanel` / `HideControls` / `Exit` / `SeekStep(direction)` / `None`，`mode` 为 `Hidden`（控制层隐藏）、`Controls`（控制层显示）、`Panel`（选项面板打开）。隐藏态：确定暂停并唤出控制层、左 / 右拖进度、上唤出控制层、下打开面板、返回退出。控制层与面板态只处理返回键，方向键与确定键一律 `None`，交给焦点所在的按钮。模式由 `PlayerHost` 判断：面板打开是 `Panel`，控制层显示且焦点不在根容器上是 `Controls`，其余是 `Hidden`。

5. **返回键不进键位表，走 `BackHandler` 三级。** 面板打开关面板，控制层显示收起控制层，都关着时不拦截、交给外层退出播放。这样三级返回都走系统返回流程，`remoteAction(Back, …)` 的 `Exit` / `ClosePanel` / `HideControls` 是给键位表作单测与文档用的穷尽定义。

6. **长按加速按连发次数分档，另挂 0.8 秒兜底提交。** `remoteSeekStep(pressCount)`：前 3 次 10 秒、4–7 次 30 秒、8–13 次 1 分钟、14 次起 5 分钟封顶；`pressCount` 取 Compose 的 `nativeKeyEvent.repeatCount + 1`。提交发生在 `KeyUp`，另有 `ScrubIdleCommit` 在目标 800 ms 没有变化时提交（有些遥控器松手不发 `KeyUp`），只挂在电视上——手机手指按住不动不能提交。别的键打断连发时先把已拖到的位置提交过去。`commit()` 幂等，KeyUp 与超时谁先到都行。

7. **`Scrubber` 是拖进度的唯一临时状态。** 手指横滑、拖进度条、遥控器连发都只改它的 `target`，`commit()` 才 `seekTo`，并且先清 `target` 再跳转，避免滑块先弹回旧位置；拖动结束时 `target` 从非空变空会重启位置轮询，滑块立刻落到松手处。时长未知时 `begin` / `dragTo` / `step` 全部拒绝，`target` 保持 `null`。手机和电视共用同一个 `Scrubber`。

8. **选项数据手机电视共用一份。** `OptionLists.kt` 的 `rememberOptionGroups(state)` 固定输出字幕、音轨、倍速、比例四组 `OptionGroup`：字幕组第一项是「关」（`disableTrackType`），没有可选轨道时该组只有一项不可选的「无」；比例是适应 / 填充 / 拉伸（`RESIZE_MODE_FIT / ZOOM / FILL`）。手机浮层和电视面板都只消费这份数据，新增一个选项不需要改两处界面。

9. **纯函数进 `playback/engine/`，配 JVM 单测。** `PlayerControlTest` 覆盖隐藏 / 控制层 / 面板三态的键位、连发步长的档位边界（0、3/4、7/8、13/14）与封顶、横滑换算的钳制与「时长未知 / 宽度为零时保持原位」；`ScrubberTest` 覆盖「拖动期间只记目标」「没拖就 commit 不跳转」「连发在目标上累加并钳制」「时长未知不能拖」「cancel 丢弃目标」。`Scrubber` 用 Compose runtime 的 `mutableStateOf`，它不依赖 Android，能在纯 JVM 单测里直接构造。

10. **文件按职责拆开，`PlayerHost` 只做分流。** `ui/player/` 下：

| 文件 | 职责 |
| --- | --- |
| `PhoneOverlay.kt` | 手机控制层：顶栏、中间三钮、底部进度条与时间 |
| `PhoneOptionsPopup.kt` | 手机顶部图标点开的浮层，选完关闭 |
| `TvOverlay.kt` | 电视控制层：标题、自绘进度条、按钮行、默认焦点 |
| `TvOptionsPanel.kt` | 电视底部玻璃面板：五列选项 + 片源格式行 + 诊断 |
| `OptionLists.kt` | 字幕 / 音轨 / 倍速 / 比例的选项数据与选择逻辑 |
| `PlayerGestures.kt` | 手机手势（含横滑拖进度）与 `Context.activity()` |
| `RemoteKeys.kt` | Compose 按键到 `RemoteKey` 的映射、键位执行、空闲提交 |
| `TransportButton.kt` | 手机电视共用的圆形图标按钮与电视焦点放大 |
| `Scrubber.kt` | 拖进度状态：目标时间、松手才跳转 |

`PlayerHost.kt` 只保留画面、手机 / 电视判断（`LocalIsTv`）、`Scrubber` 与自动隐藏、返回键、沉浸式，以及给字幕让位的 `panelHeight`。旧的一次性控制层与设置面板文件删除。

11. **电视焦点可见，面板信息集中。** 聚焦按钮放大 1.18 倍并加 2dp 白圈（150 ms 动画）；电视进度条是自绘的 6dp 轨道加圆点，本身可聚焦，聚焦时左右键走同一套连发拖进度，上下键回按钮行。默认焦点在播放 / 暂停（`FocusRequester`），面板关闭后焦点还给根容器。下键升起的玻璃面板横排五列「字幕 / 音轨 / 倍速 / 比例 / 其他」，列间左右、列内上下，确定选中即关；顶部一行是片源格式（分辨率 · 动态范围或杜比视界 profile · 帧率 · 音频格式），取代原来压在画面右上角的徽标（ADR-0042 已把统计移进诊断区）。「其他」列是画质增强、查看 / 复制诊断：画质增强选中后关面板，诊断的显示与复制留在面板内。面板最高占屏幕 70%，内容在面板内滚动。电视布局不出现任何必须触摸才能用的元素。

12. **自动隐藏的例外要按原因分开。** 播放中 4 秒无操作隐藏；暂停、正在拖进度条、遥控器 / 手势的目标还没提交、面板打开、手机选项浮层打开时都不隐藏。浮层用单独的 `onPopupOpen` 信号，不借「拖动中」——否则首次组合或销毁时会把正在进行的拖动状态清掉。

## 后果

- **不做（第二阶段）**：选集侧栏、章节列表、进度条缩略图、字幕样式设置。
- **手势与焦点仍然没有自动化测试**：仓库只有 JVM 单测，覆盖的是键位表、步长、横滑换算与 `Scrubber`；Compose 布局、真实手势手感、焦点流转只有模拟器操作加 `android/README.md` 的真机清单。只能在真机确认的有：遥控器实体键的重复率与 0.8 秒兜底是否够用、长按两倍速的触发时长、HDR / 杜比视界 / 音频直通的实际输出、刘海与系统栏行为。模拟器是软件渲染，10-bit HEVC 硬解会失败，测播放要用 8-bit H.264。
- **播放内核未动**：解码与降级、轨道、画质增强、统计与诊断、续播与进度上报都不改，只新增文件；ADR-0039 / 0040 / 0042 的结论继续有效。
- **键位语义依赖根容器焦点**：控制层显示但焦点落在按钮上时按 `Controls` 处理，方向键归焦点系统；焦点回到根容器才是隐藏态键位。这让「控制层显示时方向键只在可见按钮间移动」不需要额外的状态机，但也意味着键位表无法单独推出「现在焦点在哪」。
- **长按步长按连发次数而不是按住时长分档**，不同遥控器的键重复率差别很大，同样的按住时长在不同机器上跳过的距离可能差好几倍。
- **位置与时长仍靠控制层可见时 500 ms 轮询**（ADR-0041 第 2 条），手机与电视各实现一份，`PlayerHost` 里不共享；两句 `while (true)` 是同一份读数的两个副本。
- **手势层仍然始终挂载**：`PlayerGestures` 在手机上负责单击 / 双击 / 长按 / 竖滑 / 横滑，电视没有触屏所以不生效，但事件层照样组合在画面之上。
- 旧的一次性控制层文件删除后，`ui/player/` 之外的适配文件（`PlayerChrome.kt` 的对比按钮、`PlayerDiagnostics.kt` 的复制、`PlayerIcons.kt`、`PlayerFullscreen.kt`）继续复用，没有复制逻辑。

## 否决方案

- **只修电视焦点与手机手势**：不动结构，入口还是堆在底栏，观感提升有限，达不到规格里「接近 Infuse」的整体要求。
- **一次做完选集、章节、缩略图**：要先补后端数据（章节、缩略图切片），工期长，放第二阶段。
- **把遥控器键位散写在 Compose 的 `onKeyEvent` 里**：三种模式 × 六个键的含义变成界面代码的一部分，无法单测，改键位只能靠人肉回归；抽成 `remoteAction` 纯函数后才敢连按、长按一起改。
- **电视上直接用 Material 的 `Slider`**：它的拖拽语义要求触摸，遥控器焦点落在 thumb 上很难表达「左右键连发拖进度」，自绘进度条加 `focusFrame` 更可靠。
- **拖动过程中每帧 `seekTo`**：持续的 seek 会卡顿，滑块还会先弹回旧位置；只记目标、松手才跳转才能让画面跟手且不抖。
