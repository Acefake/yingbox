# 洗版与电影上线追踪

追剧日历页「追更」展开后多了三个标签：**剧集**（原来的追更面板）、**洗版**、**电影**。三者共用剧集追更的 115 闸门（同一条请求队列、同一份每天限额、同一个熔断），不另开 115 请求通道。只有桌面端。

前提和剧集追更一样：设置 · 网盘里填 PanSou 地址、扫码登录 115；电影上线追踪还要设置里有 TMDB 令牌。

## 洗版

片库里分辨率低于目标的电影 / 单集，每周搜一次更清楚的版本，找到只**提示**，用户点了才替换。

| 项目       | 规则                                                                                                         |
| ---------- | ------------------------------------------------------------------------------------------------------------ |
| 开关       | 默认关（每周去搜要花 115 次数）                                                                              |
| 目标       | 1080p（默认）或 4K                                                                                           |
| 洗哪些库   | 按网盘处理（CloudDrive2 挂载 115）、TMDB 识别、已匹配的电影库和剧集库；本地盘上的库不洗                      |
| 洗哪些文件 | 每个条目取分辨率最高的视频文件，文件名里写着低于目标的分辨率（720p、480p…）；认不出分辨率的不洗；第 0 季不洗 |
| 频率       | 每周清点一次片库；每个文件每周搜一次；一轮最多搜 4 个；每天最多花 60 次 115 查询                             |
| 候选       | 剧集用追更的认集规则，电影用电影规则（见下）；只要达到目标、比现在更清楚的                                   |

### 替换

1. 点「替换」：认出旧文件在 115 上的文件夹——设置里填了挂载根目录（`library.notify.mountRoot`）就按它逐级找；没填就把本地路径和 115 根目录下的文件夹名对齐后逐级找。结果按本地目录缓存。
2. 转存前列一次那个文件夹：**里面必须有旧文件**（核对不上就不存，界面展开文件夹选择器让用户选）；同名新文件已在就不再存；只传那一个 file_id。
3. 旧文件不动。新文件出现在本地挂载里后记为「已有新版」，并通知媒体库重读这个目录；一天还没出现就在记录上报错。
4. 「删旧文件」要先确认，并且新文件必须已在本地；经本地挂载删除（CloudDrive2 会同步删 115 上的文件），再通知媒体库。

## 电影上线追踪

在线详情页（电影）操作区多了一个时钟按钮「追踪上线」；电影标签页里也能按片名搜 TMDB 加入，想看清单里在线板块的片名可以一键搜。

| 项目       | 规则                                                                                                                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 开始搜     | TMDB `release_dates` 里各国最早的数字发行日（type 4）当天 20:00；没有就用实体发行日（type 5）；都没有而首映已过 120 天，从今天开始                                                                                             |
| 发行日未知 | 每 3 天向 TMDB 再要一次发行日期                                                                                                                                                                                                |
| 频率       | 发行后每天搜一次；一轮最多 3 部；每天最多花 40 次 115 查询                                                                                                                                                                     |
| 放弃       | 开始搜后 30 天没找到记为「没找到」，点「重新搜」再给 30 天。加入时早已发行的，30 天从加入当天算                                                                                                                                |
| 认文件     | 视频扩展名；片库同一个解析器解出电影（不是剧集、不是分段）；中文名或原名对得上；年份相差不超过 1；没有预告 / 枪版 / CAM 等字眼；500 MB–80 GB；文件名、文件夹或分享标题里要写明 WEB-DL / BluRay / Remux 之类的片源，或至少 720p |
| 转存方式   | 每部电影「待确认」（默认）/「全自动」；全自动要先选电影的 115 文件夹，分数 ≥ 70 直接存                                                                                                                                         |
| 存到哪     | 面板里选的电影文件夹；没选用设置里的转存目标                                                                                                                                                                                   |
| 完成       | 片库里出现这个 TMDB id 的电影；转存 10 分钟后还没入库就按 115 路径主动通知媒体库一次                                                                                                                                           |

## 代码

```
src/shared/contract/autograb-upgrade.ts   两个域：autograbUpgrade、autograbMovies
src/main/autograb/upgrade/
  quality-rules.ts   分辨率、要不要洗、候选算不算更好、每天子限额
  library-scan.ts    清点片库（listLibraries → query → getItem）
  state.ts           状态文件 userData/autograb-upgrade.json、清点结果并入记录
  plan.ts            一条记录要找什么（复用 match-rules / movie-rules）
  share-scan.ts      搜分享 → 看快照 → 认文件（finder.ts 同一套流程，带搜索与快照缓存）
  folder-path.ts     本地目录 → 115 cid
  transfer.ts        只存一个文件（先列文件夹、核对旧文件、同名不存）
  replace.ts         替换与删旧文件
  service.ts         一轮：清点 → 跟进 → 搜
  pan-adapter.ts     两个子模块共用的 115 能力
  index.ts           注册（启动 5 分钟后第一轮，之后每小时）
src/main/autograb/movies/
  movie-rules.ts     认电影文件、开始搜的日期、每天一次 / 30 天
  tmdb.ts            TMDB 搜片与发行日期解析
  state.ts           状态文件 userData/autograb-movies.json
  records.ts         写入 TMDB 信息、到发行日转为搜索中
  saver.ts           转存与入库跟进
  service.ts / index.ts
src/renderer/src/features/autograb-upgrade/
  AutograbTabs.vue（剧集 / 洗版 / 电影）、UpgradePanel.vue、MoviesPanel.vue、MovieTrackButton.vue
```

剧集追更只多了一个出口：`AutograbService.gate()` 返回加载完状态后的闸门，`registerAutograb` 把它交给两个子模块。

## 还没做

- 洗版只认文件名里的分辨率，不用 ffprobe 读真实分辨率；没写分辨率的文件不洗；
- 剧集洗版逐集搜（同一部剧连着几集共用 1 小时的搜索与快照缓存），没有整季包；
- 删旧文件走本地挂载删除，不调 115 删除接口；
- 115 登录失效的熔断由剧集追更在重新扫码后恢复（剧集栏的「恢复」也能解除），只用洗版 / 电影时要点一下；
- 本地媒体库详情页没有「追踪上线」挂点（本地库里的电影已经有文件了），只在在线详情页；
- NAS 服务端（115 会话只在 Electron 主进程）。
