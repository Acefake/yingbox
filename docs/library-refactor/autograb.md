# 追更：新集自动转存到 115

追剧日历页右上角「追更」展开面板。剧集库里已匹配 TMDB 的剧，新集播出后自动去 PanSou 搜 115 分享，验过文件后**只把那一集**存到这部剧的 115 文件夹，再由 CloudDrive2 变更通知（或追更主动通知）入库。只有桌面端（115 会话在主进程）。

## 前提

- 设置 · 网盘：填 PanSou 地址、扫码登录 115；
- 剧集库那部剧的文件夹在 115 上（CloudDrive2 挂载），媒体库存储设为「网盘」；
- 建议配好 CloudDrive2 webhook（见 [library-cloud-mode](../library-cloud-mode.md)）；没配也行，追更会在转存 10 分钟后主动通知媒体库扫描。

## 每部剧三档

| 模式         | 行为                                                           |
| ------------ | -------------------------------------------------------------- |
| 不追（默认） | 什么都不做                                                     |
| 待确认       | 搜到候选列在面板里，点「转存」才存                             |
| 全自动       | 必须先选 115 文件夹；手动确认满 3 集后，分数 ≥ 70 的候选直接存 |

## 流程（src/main/autograb）

1. **缺集**（records.ts）：每 30 分钟看一次追剧日历（往回 14 天），追更中的剧已播出、本地没有文件的正片集建一条记录；本地有了就记为已入库。每集一条，键是「剧 id:季:集」。
2. **时间**（schedule-rules.ts）：播出日 20:00 起搜；前 48 小时每 4 小时，之后每天一次；14 天没找到记为找不到。
3. **搜**（finder.ts）：「剧名 S01E05」「剧名 第5集」「剧名」依次搜，结果缓存 1 小时；分享去重、去掉拉黑的，剧名对得上的和新的优先，最多看 4 个；看快照，顶层只有一个文件夹或有对得上的季 / 剧名文件夹时点进去一层。整季包另走展开，见下文「整季包」。
4. **认文件**（match-rules.ts）：视频扩展名；片库同一个解析器解出同一集、单集；季号写明的必须相同，没写时只接受第 1 季；剧名对得上；没有预告 / 花絮 / 枪版 / CAM 等字眼；80 MB–25 GB。打分：剧名、季号、分辨率、中字、片源、体积。用户偏好接在这里，见「偏好」。
5. **转存**（saver.ts）：先列目标文件夹，同名已在就不存；查 115 剩余空间（见「空间检查」）；只传那一个 file_id；115 说「已经接收过」算成功；存完再列一次文件夹，记下新文件的 id 和体积（撤销用）；分享失效 / 提取码错拉黑 7 天、换下一个候选。
6. **核对**：日历里这一集有了文件才算完成；转存 10 分钟后还没有就按 115 路径主动通知媒体库；一天后还没有就在记录上报错。

## 115 风控（gate.ts）

- 追更的 115 请求排成一队，间隔 3–5 秒；
- 每天最多 200 次查询（含列目录、查空间）、30 次写操作（转存，以及撤销时的删除）；
- 安全验证 / 操作频繁：暂停 6 小时；48 小时内第二次就停到手动点「恢复」；
- 登录失效：停到重新扫码后自动恢复。

## 状态

`userData/autograb.json`：每部剧设置（含偏好覆盖）、全局偏好、每集记录（含转存出的文件 id / 体积、拉黑的候选）、拉黑分享、空间暂停、闸门计数。读取逐字段校验，60 天前已结束的记录自动清掉。后加的字段老文件里没有，读成默认值，版本号仍是 1。

## 日历卡片上的追更状态

追剧日历里追更中的每一集，卡片左上角有一个小标记，从追更记录按「剧 id:季:集」对上：

| 标记   | 记录状态                                 |
| ------ | ---------------------------------------- |
| 搜索中 | 等待下一次搜索                           |
| 待确认 | 有候选，等点「转存」                     |
| 已转存 | 已存进 115，还没主动通知媒体库           |
| 入库中 | 已存进 115，已通知媒体库扫描             |
| 失败   | 找不到 / 115 空间不足 / 转存一天仍没入库 |

已入库、已跳过不显示。悬停看原因；点标记展开追更面板并滚到那一集（高亮）。标记是卡片外的另一个按钮，不和卡片的「播放 / 打开详情」嵌套。

面板和日历共用一份总览（features/autograb/autograb-store.ts）：preload 的 offChanged 会移除通道上全部监听，所以按使用者计数，最后一个离开才退订。

## 整季包（finder.ts、pack-rules.ts）

整季包里缺的那一集常在第二页之后，或在「剧名 / 第 1 季 / 11-20」这样更深的文件夹里，只看顶层和一层文件夹的第一页（100 条）找不到。所以：

- **认出合集**：分享标题或顶层文件夹名像「全 30 集」「合集」「Season 1」「S01」「01-10 集」「更新至」，或一页装不下；
- **展开**：广度优先，最多下 3 层；每个文件夹按 offset 翻页（最多 5 页）；子文件夹带季号的只点同一季，带集数区间的只点包含这一集的，名字对得上剧名的点，其它（「4K」「国语」）只在这一层不超过 3 个文件夹时点；
- **限速**：每个分享最多 10 次快照，全部经闸门；挑到这一集就停；
- **只存一个文件**：用同一个认文件规则挑出那一集的单个 file_id 转存；合并成一个文件的多集（E15-E16）仍然拒绝。

## 偏好（shared/contract/autograb-prefs.ts）

面板右上「偏好」改全局，每部剧一行的「偏好」改这部剧的覆盖项：

| 项         | 规则                                                                                  |
| ---------- | ------------------------------------------------------------------------------------- |
| 首选分辨率 | 2160p / 1080p / 720p / 任意。命中 +15，别的已知分辨率 −5；任意时沿用「越清晰越高」    |
| 偏好词     | 字幕组、片源等，按子串不分大小写，在文件名 / 文件夹 / 分享标题里命中每个 +6，最多 +18 |
| 排除词     | 文件名或所在文件夹命中即拒（内置的预告、枪版等照旧）                                  |
| 体积       | 下限 / 上限（GB 输入，存 MB），替换默认的 80 MB–25 GB                                 |

合并：排除词全局与每剧叠加；其余字段每剧设了就用它的，空着跟随全局。改偏好只影响之后的搜索，已列出的候选不重新打分（点「重新搜」即可）。

## 空间检查（saver.ts）

真要转存时（目标文件夹里还没有同名文件），先查 115 剩余空间（`/files/index_info`，经闸门）。剩余小于「候选体积 + 1 GB」：

- 这一集记为「空间不足」，候选保留；
- 全局暂停自动转存（`spacePause`），面板顶部提示；搜索照常；
- 解除：清理空间后点「恢复」，或手动转存一集成功。

## 撤销（revert.ts）

已转存（或已入库）的集，面板里有「撤销」，确认后：

1. 列记录里的那个 115 文件夹，按记下的文件 id 找到文件，**文件名和体积都和转存时一致**才删；对不上、找不到都不删，报原因；
2. 只删那一个文件（`/rb/delete`，进 115 回收站），经闸门，计入写操作限额；
3. 记录回到缺集、马上重新搜；这个候选（分享码 / 分享内文件 id）拉黑，以后不再列出；
4. 媒体库：发一条删除通知，本地记录交给片库下次刷新处理。刷新前日历里还挂着被删的文件，按文件名认出来，不会把这一集又记成已入库；日历里换成别的文件才算入库。

没有记下文件 id 的记录（加上撤销之前转存的、或同名文件本来就在的）不能撤销，请在 115 里手动删。

## 还没做

- NAS 服务端（115 会话只在 Electron 主进程）；
- 改偏好后自动给已列出的候选重新打分；
- 撤销与查重只看目标文件夹第一页（200 条，新上传的在前），文件夹特别大时可能找不到文件。
