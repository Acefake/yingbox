# 新入库：自动中文字幕与入库推送

设置 ·「新入库」分区（只有桌面端）：

- **推送渠道**：系统通知、Bark（服务器地址 + 设备 key）、Telegram Bot（token + chat id），每个渠道有「测试」；
- **推送什么**：追更的集入库、新剧集、新电影，各自一个开关；「合并推送」把 1 分钟内的多条合成一条；
- **自动中文字幕**：新入库时自动下载（默认关）、每天最多几份（默认 5）。

两件事共用同一个来源：片库引擎宣布的「新入库」。

## 新入库（src/main/library/arrivals）

片库引擎里的 intake 看片库自己的事件（扫描后的 `items-changed`、识别结束的 `identify-progress`），静 5 秒后扫一轮：

1. 取水位之后入库、有视频文件的电影 / 集（`arrival-store.ts`），连同顶层条目（电影本身 / 剧）的片名、识别时间；
2. 可以宣布的（`arrival-rules.ts`）：顶层条目在这个条目入库之后识别过，或库没开自动识别，或入库已满 10 分钟（识别迟迟不来时用文件名解析的片名）；
3. 水位停在最早一个还要等的条目之前，已宣布的记在游标里（片库设置表 `arrivals.cursor`），同一条只宣布一次；
4. 第一次运行时水位定在当下：打开功能之前就在库里的不宣布。

结果走线协议事件 `library:arrivals`（`shared/library/arrivals.ts`）交给主进程；同一批也交给自动字幕。

intake 只读数据库、只往外交结果，不排片库任务，所以挂在事件上而不是任务后继（ADR-0012 管的是处理链）。一轮是幂等的，引擎重启后由启动时的一轮补上。独立服务（NAS）不给 `onArrivals` 和字幕设置，intake 不启动。

## 自动中文字幕（src/main/library/subtitles）

在片库引擎里做：OpenSubtitles API key 本来就存在片库设置里（媒体库设置 · 元数据），视频路径、网盘判定、ffprobe 也都在这边。开关和每日上限是主进程设置 `subtitles.auto.*`，引擎每轮开始前经代办方法 `subtitleSettings` 要一次。

每个视频（键是条目 id，状态存片库设置表 `subtitles.auto.state`）：

| 情况                                                                                    | 结果                                                                                                 |
| --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 远程源（`yingbox-dav://`）                                                              | 跳过：WebDAV 上不能写                                                                                |
| 番号库                                                                                  | 跳过                                                                                                 |
| 文件名写了中字 / 简中 / 中英 / chs / cht                                                | 已有                                                                                                 |
| 同名外挂字幕带中文后缀（zh、chs、cht、chi、sc、tc、简、繁…），或无后缀但内容是中文      | 已有                                                                                                 |
| 内封字幕流 language 是 chi / zho / zh，或标题写着中文（只探测本地库；网盘不读视频内容） | 已有                                                                                                 |
| 文件夹不可写（先 access，再真写一个空文件；网盘挂载常常 access 说能写）                 | 跳过并记原因                                                                                         |
| 没识别到 TMDB、也没有文件哈希                                                           | 跳过（按片名搜太容易下错）                                                                           |
| 搜到人工中文字幕                                                                        | 下载，存成 `<视频名>.zh.srt`（繁体 `.zh-TW.srt`），UTF-8 带 BOM，先写 `.part` 再改名，同名已在不覆盖 |
| 没搜到 / 网络失败                                                                       | 1 小时、6 小时、1 天后各再试一次，都没有就跳过                                                       |

搜索：电影按 `tmdb_id`，集按剧的 `parent_tmdb_id` + 季集；本地文件带上 moviehash（扫描时算的指纹）。挑选：哈希命中 > 简体 > 可信上传 > 下载量，听障版靠后，机翻 / AI 翻译不要。

限速与额度：两次请求至少隔 1.5 秒、一次一个；每天最多 `dailyLimit` 份（本地日期清零），到了就把等着的推到明天零点；OpenSubtitles 回 406 / 429 同样停到明天、不算失败；key 没配或无效时整轮停，下次有新入库再试。

## 入库推送（src/main/notify）

- `notify-rules.ts`：新入库 / 追更入库 → 推送项（去重键：电影 `movie:<id>`，集 `ep:<剧 id>:<季>:<集>`），一批 → 一条消息（多条时标题写总数，正文最多 8 行）；
- `notify-service.ts`：按类型开关过滤，同一个键 24 小时内只推一次；合并开着时第一条进来起等 60 秒一起发；某个渠道失败只记日志；
- `channels.ts`：Bark `POST <服务器>/push`（JSON，分组「影盒」）；Telegram `sendMessage`；不跟随重定向，超时 15 秒，报错前把 key / token 打码；
- `index.ts`：读设置和密钥（`notify.bark.key`、`notify.telegram.token` 走 safeStorage，渲染层只写不读），系统通知用 Electron `Notification`，出网用 `net.fetch`（走系统代理，国内连 Telegram 通常要代理）。

追更：片库先看到这一集时，问追更「这一集是不是转存了还在等入库」（`isSaved`），是就标成「追更已入库」；追更自己的一轮发现转存过的集在日历里有了文件时也交一次（`landed`），同一个去重键，所以不会推两次。

## 测试

- `tests/library/engine/arrivals.test.ts`：水位规则；真实片库里扫进来的电影 / 集宣布一次、打开之前的不宣布、等识别的宽限期；
- `tests/library/subtitles/*.test.ts`：中文字幕判断、挑选、命名、重试；假 OpenSubtitles 下的下载、已有字幕、远程源、重试、每日上限、额度用完、关闭；
- `tests/notify.test.ts`：消息格式、追更标记与去重、类型开关、合并、Bark / Telegram 请求与打码、追更 `landed`；
- `tests/notify-settings-ui.test.ts`：设置分区的纯规则。

## 还没做

- 打开自动字幕之前已经入库的条目不补；设置页里看不到每个视频的字幕状态（只在日志里）；
- NAS 独立服务没有推送和自动字幕；
- 字幕语言只要中文，没有「中英双语优先」之类的偏好。
