## 排查：保存的设置不持久化

- 结论方向：localStorage 写入链路本身正常（`%APPDATA%/yingbox/Local Storage/leveldb` 中唯一 origin 为 `http://127.0.0.1:3000`，`yingbox-theme`/`scrapeConcurrency`/`av_missav_catalog_v1` 等键都在）。
- 主要疑点：启动时 `AppLayout.vue:425` → `refreshSources()` → `use-source-refresh.ts:68 checkAll()`，对每个源做 8s 探测，**探测失败的源直接 `selectedSites.delete()` / `avEnabledApis.delete()`**，两者都是 `useStorage` 持久化的 → 用户手选的数据源被连通性覆盖（只有"全部源都失败"才 return 保留）。
- 次要点：`syncAvSources()` 启动即跑且自动启用新源；`use-online-search.ts:154` 当存值等于旧 fallback 列表时会重写成全部非成人源。
- 潜在放大因素：`electron.vite.config.ts` 渲染层端口 3000 `strictPort: false`，3000 被占用时端口漂移 → origin 变化 → 整套 localStorage 看起来"归零"；dev(file:// vs http://127.0.0.1:3000)与打包版（`%APPDATA%/影盒`）天然两套存储。
